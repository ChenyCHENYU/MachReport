# MachReport 项目评审与收敛建议

评审更新：2026-10-15。初始基线为 `main` 的 `812b110`（2.0.0），本文记录输出修复、接入收敛以及2.1–2.3的使用体验改进。本文区分实际实现、已修复问题和待演进能力，不将路线图视为现有功能。

2.3.1进一步复查修复了宿主CSS污染几何、跨出口字体/内距/行高、PDF临界行高误裁、XLSX合并覆盖行高、打印尺寸取整与生命周期等真实问题。所有生产函数启用complexity≤20硬门禁，单测与浏览器测试默认零重试。**597项单测、20项Chromium回归及完整verify通过**。具体测量、样式隔离与当前出口边界见[质量与还原说明](./QUALITY.md)。下方历史问题和数据保留各自版本背景，以该说明中的最新验证为准。

## 产品结论

MachReport 已具备可复用报表引擎的主要骨架：模板 DSL / JSON → 排版计划 → 多种渲染与导出。生产日报等业务宽表按完整自然列宽展示，出入库单、工艺卡、订单明细和分组汇总可选择标准纸张、分页与打印。

**支持 Excel `.xlsx` 导出，2.3增加完整宽表与连续 Sheet。** wide 默认保留原始值并按逻辑表连续导出，普通页面保留逐页 Sheet / 显示文本的旧行为；支持表格结构、合并、对齐与部分样式。没有Excel模板导入、完整工作簿设计器或公式计算引擎。详见 [Excel 能力矩阵与示例](./EXCEL.md)。

建议保留“独立页面报表引擎 + Vue 预览”的产品主线。MachTable 负责在线数据列表、筛选和编辑；MachReport 负责排版、分页、预览和输出。两者统一品牌与接入体验，避免各自重复建设完整数据网格或 Excel 编辑器。

## 架构评价

| 层次 | 现状 | 判断 |
| --- | --- | --- |
| 模板 / 分页 | `builder`、`layout` 将业务数据转为 `RenderPlan` | 适合稳定为核心协议；应强化跨后端一致性 |
| 页面协议 | 毫米几何、组件、网格、富文本、样式 | 足以承载页面输出；不是原始数据或工作簿模型 |
| 渲染 | DOM、Canvas、PDF 分别消费计划，复用几何与样式工具 | 分层合理，但实际支持矩阵仍有差异 |
| Excel | `/xlsx` 用 ExcelJS 生成工作簿，按逻辑表元数据连续导出宽表 | 保留按需出口；不按显示文字猜测重复行 |
| Vue | 预览、参数、搜索、缩略图、虚拟化、配置和控制器 | 接入完整，需继续收敛异步与资源生命周期 |
| 数据接入 | 注入 `PlanFetcher`，本地适配器复用分页器 | 独立性很好，应继续由宿主管理接口与鉴权 |
| SQL | 可选动态 SQL 编译与检查 | 不应承担后端授权或数据库只读保障 |
| 部署 | 单 npm 包 + 独立 federation 部署件 | 普通接入优先 npm；联邦用于有远程组件需求的宿主 |

核心不依赖 Vue、ExcelJS 或 PDF / SQL 实现。重依赖被内联进独立子入口；“零运行时依赖”不代表这些出口体积为零。公开 Workbook 类型包含 Node stream API，因此提供 `@types/node` 类型依赖。

## 对照 MachTable：本轮接入收敛

基于 MachTable 的适配入口、查询编排和 `useMachTable` 使用方式，MachReport 原先仍要求宿主完成模板到计划的连接，以及父页面的控制器接线。本轮将常规流程收进同一份框架无关数据源，并由 Vue 插件直接消费。

| 使用侧原先承担 | 现在的包内职责 | 保留的业务职责 |
| --- | --- | --- |
| 手写 ID 判断、分页、页合并和校验 | 插件 `reports` / 核心 `createReportSource` | 报表 ID、模板和数据范围 |
| 业务响应转数据集，并手写后续排版 | `defineReport` 推导取数类型并衔接映射、分页 | 取数函数与明确字段映射 |
| 重复传模板参数定义 | 数据源提供参数元数据，组件自动显示面板 | 参数本身的业务含义 |
| 导入核心与 Vue 两个入口 | `/vue` 重导出同一套核心 API 与类型 | 按需选择 PDF / XLSX / SQL 出口 |
| 手写父组件 ref 类型与可选链 | `useMachReport` 提供稳定 ref / ready / 控制方法 | 页面操作与结果提示 |
| 旧请求取消、过期告警、重复导出协调 | 统一 signal、代际隔离、导出去重及卸载清理 | 请求客户端消费 signal、事件处理 |
| 局部文案与主题要求重复整份配置 | defaults / preset / 路由按字段继承 | 局部差异配置 |

常规页面现在只需 `<MachReportPreview report-id="outbound" :params="{ orderId }" />`。插件注册模板及业务取数，包内完成其余编排；高级自定义 fetcher、本地适配器、原 ref 和后代控制器仍保留。没有新增后端依赖或报表服务。完整示例见[项目接入指南](./INTEGRATION.md)。

此次同时修正完整响应体超时、已有查询参数合并、异步插件注册开关和同名组件覆盖，并补齐 `autoLoad=false` 手动加载后的过期结果清理。同步分页仍不可抢占；真实 HTTP 取消依赖业务请求客户端消费 signal。控制器可等待工作结束，输出失败保持走原来的 error 事件契约。

## 三项使用体验改进（2.1.0）

| 维度 | 包内新增能力 | 使用侧减少的工作 |
| --- | --- | --- |
| 预览 / 导出状态 | `useMachReport().state` 提供稳定只读响应式对象，统一加载、页数、导出、打印、错误与字体状态 | 无需通过多个事件重复维护 loading、按钮禁用和错误状态；可解构 `state` |
| 首次 PDF 字体诊断 | 有效预览后共享 HEAD 检查、取消与超时、重试提示；实际导出严格解析字体与字符覆盖，修复坏缓存 | 无需在业务页面另建字体探测和错误分支；只配置字体 URL |
| 标准明细模板 | `createTableTemplate` 默认纸张、边距、标题和数据集，按固定宽度 / 权重分配列宽，沿用现有分页和汇总 | 普通明细仅定义标题与业务列，不手算毫米坐标和宽度 |

新能力保留旧 fetcher、六方法控制器、自定义 PDF 函数与自由布局 DSL。字体预检不加载 PDF 引擎、不下载字库、不阻塞预览；资源可达与字库字符覆盖明确区分。独立复查补充了旧严格字体请求失败不能清除新代际缓存的竞态回归。标准模板和状态句柄在真实打包消费端检查，示例增加同一注册方式的标准明细报表。

详见 [接入指南](./INTEGRATION.md)、[API](./API.md) 与 [PDF 字体指南](./PDF.md)。

## 输出与工程修复

2.2本轮进一步完善表头与内容独立对齐、JSON模板管理基础和大计划预览。标准工厂默认表头居中、真实数字居右、文本居左；旧低层模板未用新字段时保持兼容。模板文档有明确协议版本与宿主revision，支持校验、导入导出、独立目录快照和异步加载；管理UI、权限、审批和持久化仍由宿主负责。

正文复用页尺寸索引，缩略图也按窗口挂载并释放离屏画布；搜索分片、取消与按页累计命中。1000页真实Chromium fixture验证正文和缩略图节点有界，完整计划仍在内存，不能据此推导任意行数恒定内存或网络/分页/导出零阻塞。新增`preview`/`xlsx`配置均按字段继承。模板与数据异步期间，报表ID和参数使用调用入口快照。

Excel增加原始值与数字格式、自动A3/A4/A5纸型，修复垂直对齐、字体优先级及无边框输出。它不复制绝对空间坐标。2.3进一步补齐自然列宽预览、稳定逻辑表元数据、连续Sheet和可选打印纸型；图片保真、自由矩阵的严格坐标映射与大数据流式输出仍需独立验收。

## 完整宽表与纸型选配（2.3.0）

`createTableTemplate({ layout: "wide", columns })` 使用全部列的自然宽度，自动列默认30mm，列级固定宽度与flex仍有效。预览默认100%，横向滚动查看全部列，内部纵向块保持窗口化；适宽允许真正缩至整个表宽，缩略图按目标宽度生成，避免为超宽表创建巨幅缩略画布。标准page模式保持旧行为，A3/A4模板与Excel打印纸型均可按业务选择。

分页器生成表ID、逻辑行索引、角色与列身份；多报表合并时隔离ID。Excel默认auto只把明确标记的宽表还原为连续Sheet，重复页头去重不依赖文字；无元数据的自由布局不会被猜测合并。宽表默认不强制A4或打印缩放，显式paperSize仅改变打印设置，不压缩实际数据列宽。

移除3000mm的人为模板宽度上限，保留有限正尺寸和总宽溢出检查。Excel真实行列格式上限明确报错，不截断后宣称成功。完整计划和工作簿仍在内存，DOM窗口化不等于无限数据量；单个横向块的全部列仍会挂载，后续列窗口化与流式导出应以真实业务基准驱动。

| 问题 | 原来的影响 | 本次处理 |
| --- | --- | --- |
| 列宽与列数未进入计划 | 不等宽列退回均分；跨前两列的小计会丢第三列金额 | 表头、明细、组头、小计和总计统一携带列宽 |
| 小计与总计共用标签跨度 | 两种汇总字段位置不同时，小计值被标签覆盖 | 各自按实际汇总字段确定跨度 |
| 列表字号未传给渲染样式 | 行高按指定字号计算，实际文字仍用默认字号 | 传递列表字号并保留显式样式覆盖 |
| DSL 纸张选项被忽略 | `.page("a4", { landscape, margins })` 不生效 | 正确读取第二参数，保留数值纸张的旧签名 |
| XLSX 合并越界 | 跨行覆盖后续组件，或抛重复合并异常 | 合并范围裁剪到当前网格 |
| XLSX 标题列数错误 | 将毫米换算的列宽误当列数，70 mm 标题横跨 38 列 | 按真实表格列数合并，纯文本页单列输出 |
| 导出遗漏没有提示 | 富文本、嵌套内容和形状可能静默消失 | 对未支持内容返回 XLSX 告警 |
| 计划必需字段校验不足 | 缺少 `components` / 几何字段仍通过，渲染时崩溃 | 提前拒绝缺字段、非有限数和负尺寸 |
| Vue 加载状态早退 | 加载中清空 ID 后一直显示加载，错误被遮盖 | 新请求统一复位；卸载后旧请求结果失效 |
| SQL 执行注释绕过 | MySQL / MariaDB 可执行注释被当普通注释忽略 | 编译前、替换后、只读检查前均拒绝；覆盖转义模式差异 |
| 开发工具配置漂移 | pnpm 11 忽略旧构建白名单，首次安装失败 | 使用 `allowBuilds`，明确开发 Node ≥ 22.13 |
| CI 顺序错误 | 单测先于构建，部分产物守卫跳过、联邦产物缺失 | 统一 `verify`，先构建再测真实产物 |
| npm 类型漏依赖 | `/xlsx` 在独立 TypeScript 项目报找不到 ExcelJS | 聚合声明、内联 ExcelJS 类型、补 Node 类型依赖 |
| Vue 公开声明约束错误 | 严格消费端无法检查全局组件 / 指令类型 | 保留全局类型字段并转换为满足约束的映射类型 |
| 中文 PDF 示例缺字体 | 新 clone 后 PDF 下载和窗口测试失败 | 入库约 64 KB 的 OFL 字体子集，示例显式配置 |
| 文档与包页脱节 | README 未显示品牌资产；npm 相对链接失效；授权入口缺失 | 重构 README、Logo、文档地图、发布链接转换与授权文件 |

超出整页高度的行已增加告警，仍未实现自动拆行。SQL 修复只处理已复现绕过，不代表 SQL 检查构成执行沙箱。[MySQL 官方文档](https://dev.mysql.com/doc/refman/8.4/en/comments.html)说明可执行注释会被服务端解释执行。

## Excel 演进应单独建模

2.3以 `PlanTableFragment` 明确逻辑表身份、列结构和行角色，已支持分页列表的连续Sheet。未来独立的 `DatasetExportSpec` 可补充原生日期、流式数据与工作簿特有语义，避免从自由页面坐标猜测业务数据。

推荐顺序：

1. 日期类型与显式业务数据模型（数值 / 布尔 / 前导零文本规则已在2.2落地）；
2. 在已有连续单Sheet与分页标题去重的基础上，完善工作簿交互配置；
3. 大数据分批处理、进度与取消、服务端流式输出；
4. 只有真实业务确需时，再独立评估 Excel 模板导入或公式功能。

设计器、管理控制台、完整工作簿编辑器、SQL 数据服务均应独立立项，避免全部进入当前引擎主包。

## 性能与依赖治理

2.1.0 构建的 ESM 入口 gzip 约为：主入口 14.6 KB（初轮 12.3 KB）、XLSX 303 KB、PDF 548 KB、SQL 581 KB。新增数据源与标准模板使用原分页器，未引入运行时代码依赖。以上是入口文件本身，不含共享分片、字体或整个应用，也不是性能承诺。按需导入是必要设计。

下一轮优先建立完整依赖图 gzip 预算及真实大报表导出基准，再讨论 Worker 或换库。第三方实现虽声明在 `devDependencies`，仍会随子入口打包交付，依赖审计必须覆盖这些被内联的库，不能只执行生产依赖审计。

pnpm 11 的旧构建白名单迁移依据见[官方发布说明](https://pnpm.io/blog/releases/11.0)。本次保持锁定的 pnpm 版本，未做全工作区依赖升级。
