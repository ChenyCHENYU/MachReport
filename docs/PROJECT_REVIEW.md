# MachReport 项目评审与收敛建议

评审日期：2026-10-14。基于 `main` 的 `812b110` 及本次本地修复；源码发布包版本为 `2.0.0`。本文区分实际实现、已修复问题和待演进能力，不将路线图视为现有功能。

## 产品结论

MachReport 已具备可复用报表引擎的主要骨架：模板 DSL / JSON → 分页计划 → 多种渲染与导出。最有价值的场景是出入库单、工艺卡、订单明细和分组汇总等**具有明确纸张、分页与打印要求的业务单据**。

**支持 Excel `.xlsx` 导出，但当前以渲染后的文本为单元格值。** 每页一个 Sheet，支持表格结构、合并和部分样式；没有 Excel 模板导入、完整工作簿设计器或公式计算引擎。详见 [Excel 能力矩阵与示例](./EXCEL.md)。

建议保留“独立页面报表引擎 + Vue 预览”的产品主线。MachTable 负责在线数据列表、筛选和编辑；MachReport 负责排版、分页、预览和输出。两者统一品牌与接入体验，避免各自重复建设完整数据网格或 Excel 编辑器。

## 架构评价

| 层次 | 现状 | 判断 |
| --- | --- | --- |
| 模板 / 分页 | `builder`、`layout` 将业务数据转为 `RenderPlan` | 适合稳定为核心协议；应强化跨后端一致性 |
| 页面协议 | 毫米几何、组件、网格、富文本、样式 | 足以承载页面输出；不是原始数据或工作簿模型 |
| 渲染 | DOM、Canvas、PDF 分别消费计划，复用几何与样式工具 | 分层合理，但实际支持矩阵仍有差异 |
| Excel | `/xlsx` 用 ExcelJS 生成工作簿 | 保留为按需出口，后续单独设计数据导出语义 |
| Vue | 预览、参数、搜索、缩略图、虚拟化、配置和控制器 | 接入完整，需继续收敛异步与资源生命周期 |
| 数据接入 | 注入 `PlanFetcher`，本地适配器复用分页器 | 独立性很好，应继续由宿主管理接口与鉴权 |
| SQL | 可选动态 SQL 编译与检查 | 不应承担后端授权或数据库只读保障 |
| 部署 | 单 npm 包 + 独立 federation 部署件 | 普通接入优先 npm；联邦用于有远程组件需求的宿主 |

核心不依赖 Vue、ExcelJS 或 PDF / SQL 实现。重依赖被内联进独立子入口；“零运行时依赖”不代表这些出口体积为零。公开 Workbook 类型包含 Node stream API，因此提供 `@types/node` 类型依赖。

## 本次已修复

| 问题 | 原来的影响 | 本次处理 |
| --- | --- | --- |
| 列宽与列数未进入计划 | 不等宽列退回均分；跨前两列的小计会丢第三列金额 | 表头、明细、组头、小计和总计统一携带列宽 |
| 小计与总计共用标签跨度 | 两种汇总字段位置不同时，小计值被标签覆盖 | 各自按实际汇总字段确定跨度 |
| 列表字号未传给渲染样式 | 行高按指定字号计算，实际文字仍用默认字号 | 传递列表字号并保留显式样式覆盖 |
| DSL 纸张选项被忽略 | `.page("a4", { landscape, margins })` 不生效 | 正确读取第二参数，保留数值纸张的旧签名 |
| XLSX 合并越界 | 跨行覆盖后续组件，或抛重复合并异常 | 合并范围裁剪到当前网格 |
| XLSX 标题列数错误 | 将毫米换算的列宽误当列数，70 mm 标题横跨 38 列 | 按真实表格列数合并，纯文本页单列输出 |
| 导出遗漏没有提示 | 富文本、嵌套内容和形状可能静默消失 | 对未支持内容返回 XLSX 告警 |
| 计划必需字段校验不足 | 缺少 `components` / 几何字段仍通过，渲染时崩溃 | 提前拒绝缺字段、非有限数和负尺寸 |
| Vue 加载状态早退 | 加载中清空 ID 后一直显示加载，错误被遮盖 | 新请求统一复位；卸载后旧请求结果失效 |
| SQL 执行注释绕过 | MySQL / MariaDB 可执行注释被当普通注释忽略 | 编译前、替换后、只读检查前均拒绝；覆盖转义模式差异 |
| 开发工具配置漂移 | pnpm 11 忽略旧构建白名单，首次安装失败 | 使用 `allowBuilds`，明确开发 Node ≥ 22.13 |
| CI 顺序错误 | 单测先于构建，部分产物守卫跳过、联邦产物缺失 | 统一 `verify`，先构建再测真实产物 |
| npm 类型漏依赖 | `/xlsx` 在独立 TypeScript 项目报找不到 ExcelJS | 聚合声明、内联 ExcelJS 类型、补 Node 类型依赖 |
| Vue 公开声明约束错误 | 严格消费端无法检查全局组件 / 指令类型 | 保留全局类型字段并转换为满足约束的映射类型 |
| 中文 PDF 示例缺字体 | 新 clone 后 PDF 下载和窗口测试失败 | 入库约 64 KB 的 OFL 字体子集，示例显式配置 |
| 文档与包页脱节 | README 未显示品牌资产；npm 相对链接失效；授权入口缺失 | 重构 README、Logo、文档地图、发布链接转换与授权文件 |

超出整页高度的行已增加告警，仍未实现自动拆行。SQL 修复只处理已复现绕过，不代表 SQL 检查构成执行沙箱。[MySQL 官方文档](https://dev.mysql.com/doc/refman/8.4/en/comments.html)说明可执行注释会被服务端解释执行。

## 下一步：先补输出正确性

优先级按可能造成数据遗漏、错误输出或维护成本排序。以下仍是待办。

| 优先级 | 具体问题与证据 | 建议与验收标准 |
| --- | --- | --- |
| P1 | [Canvas](../packages/mach-report/src/render/canvas.ts) 未绘制 image / barcode / qrcode / chart；PNG 和缩略图可能丢内容 | 增加异步图片解码及取消机制；PNG 像素断言覆盖 Logo、二维码与跨域失败告警 |
| P1 | [分页](../packages/mach-report/src/layout/paginate.ts) 的组头保留下一行使用空行高度，真实首行很高时仍可能孤立组头 | 使用真实首行测量；覆盖“短组结束 + 下一组长首行”的边界 |
| P1 | 单行高于整页时仅告警，内容可能截断 | 明确策略：拆行、缩放或拒绝；选择一种默认行为并返回稳定告警码 |
| P1 | [DOM 文本](../packages/mach-report/src/render/dom.ts) 内外层重复应用旋转 / 透明度；Canvas/PDF 支持也不完整 | 明确外层几何与内层文字样式职责，建立跨后端样式契约和视觉用例 |
| P1 | [计划校验](../packages/mach-report/src/schema/validate.ts) 尚未全面检查富文本 segment、跨度、行列尺寸等深层字段 | 例如 `segments: [null]` 应在渲染前拒绝；补嵌套深度和规模上限 |
| P2 | [请求适配器](../packages/mach-report/src/vue/adapters.ts) 超时在响应头到达后结束，慢 JSON body 不受限制；已有 query 时拼接第二个 `?` | 覆盖完整响应读取周期，用 URL / URLSearchParams 合并查询参数 |
| P2 | [导出 composable](../packages/mach-report/src/vue/composables/usePrintExport.ts) XLSX 无并发去重；各格式忙碌状态可能互相清除 | 统一任务状态、取消和重复点击策略；用同一对象管理结果与告警 |
| P2 | [SQL 检查](../packages/mach-report/src/sql/compile.ts) 正则对字符串内分号等存在误判，原样替换仍需宿主约束 | 共用词法分析器；值一律绑定，动态标识符采用白名单，方言降级明确记录 |
| P2 | 单元覆盖率统计集中在 layout / render / format，尚无全域阈值 | 把 schema、Vue 生命周期与导出纳入预算；先建立实际基线，再按改动逐步提高 |

## Excel 演进应单独建模

建议引入 `DatasetExportSpec` 一类独立契约，包含字段、原始值类型、Excel 数字格式、Sheet 规则与分组语义。页面导出继续使用 `RenderPlan`，业务数据导出使用原始数据；明确支持两条路线后再考虑统一入口。

推荐顺序：

1. 数值 / 日期 / 布尔类型、前导零与长 ID 的显式规则；
2. 连续单 Sheet、分页标题去重、冻结窗格和自动筛选；
3. 大数据分批处理、进度与取消、服务端流式输出；
4. 只有真实业务确需时，再独立评估 Excel 模板导入或公式功能。

设计器、管理控制台、完整工作簿编辑器、SQL 数据服务均应独立立项，避免全部进入当前引擎主包。

## 性能与依赖治理

本次构建的 ESM 入口 gzip 约为：主入口 12.3 KB、XLSX 303 KB、PDF 547 KB、SQL 581 KB。以上是入口文件本身，不含共享分片、字体或整个应用，也不是性能承诺。按需导入是必要设计。

下一轮优先建立完整依赖图 gzip 预算及真实大报表导出基准，再讨论 Worker 或换库。第三方实现虽声明在 `devDependencies`，仍会随子入口打包交付，依赖审计必须覆盖这些被内联的库，不能只执行生产依赖审计。

pnpm 11 的旧构建白名单迁移依据见[官方发布说明](https://pnpm.io/blog/releases/11.0)。本次保持锁定的 pnpm 版本，未做全工作区依赖升级。

2026-10-14 使用 npm 官方审计端点检查完整锁文件，结果从 **1 项高危 + 1 项中危** 降至 **0 项高危、1 项中危**：

- 已将 `source-map-js` 约束到已发布的 `1.2.2`，修复索引源码映射偏移导致的拒绝服务问题，见 [GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)。锁文件安装验证通过。
- 剩余 `sprintf-js@1.0.3` 来自 `vite-plugin-dts → API Extractor → ts-command-line → argparse` 构建依赖链。公告标注 `>=1.1.4` 修复，但本次查询 npm 官方仓库实际最新版本为 `1.1.3`，直接安装 `1.1.4` 返回无匹配版本。因此没有保留不可安装的覆盖配置，待修复版本发布后升级并复核，见 [GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c)。审计命令目前仍以非零状态退出，不应描述为审计全通过。

复查命令：`pnpm audit --registry=https://registry.npmjs.org`。以上是锁文件审计结果，不等价于对所有可达攻击路径的证明。

## 验证与实际范围

统一命令：

```bash
pnpm install --frozen-lockfile
pnpm verify
pnpm test:e2e --retries=0
```

`verify` 覆盖类型、零警告 ESLint、全部工作区构建、单元覆盖率、构建产物守卫、文档链接，以及真实 npm tarball 的 ESM / CJS 运行和严格 TypeScript 消费。隔离消费检查没有安装 ExcelJS、pdf-lib 或 SQL parser，保留 `skipLibCheck: false` 和 `types: []`。

本次环境为 Node 24.19.0、pnpm 11.8.0、Chromium。发布包仍声明 Node ≥ 18，Vue peer 仍为 `^3.2.0`；最低 Node / Vue 版本以及 Firefox / WebKit 尚未形成消费端矩阵，应作为后续兼容性门禁补齐。
