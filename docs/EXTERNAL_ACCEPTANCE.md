# Office、辅助技术与设备验收

自动化已经覆盖真实PDF内容/页面尺寸、XLSX回读、码图独立解码、浏览器像素、键盘和可访问树。Microsoft Office排版、驱动实际出纸、扫码枪识别与屏幕阅读器播报仍须在相应环境执行；生成验收包不会将这些项目标为通过。

## 生成可交接的样例

先构建，再运行：

```sh
pnpm build
pnpm check:acceptance
# 保存到指定空目录，已有证据不会覆盖：
node scripts/create-acceptance-pack.mjs --out=/absolute/path/to/acceptance
```

脚本使用当前构建的真实引擎，生成严格PDF、XLSX、HTML、Word兼容HTML `.doc`、PNG码图、渲染计划、脱敏合成数据及SHA-256清单；不会生成 `.docx`。生成时回读PDF物理尺寸、Excel真实零值/编号/高精度字符串及富文本/图片，并以独立ZXing解码QR和Code128。生成失败会中止，不交付成功清单。

验收包中 `manifest.json` 记录SDK版本和样例摘要；`results.json` 的人工状态初始为 `not-run`、各项 `passed:null`。演示字库仅包含样例所需字符，不是生产完整中文字库；同包包含OFL许可。

## 屏幕阅读器与键盘流程

启动示例后，使用目标浏览器和辅助技术；记录其版本。自动化 `pnpm test:a11y` 同时保留每个状态的axe报告，可作为人工复查参考。

1. 进入普通预览，只用Tab/Shift+Tab到工具栏；能识别搜索、目录、缩放、导出和设置，焦点始终可见。
2. 打开内容搜索，输入文本并定位结果；确认当前位置/结果信息可理解。Esc关闭后焦点回到触发按钮。
3. 打开字段目录，用方向键/Home/End/Enter选择字段；中文输入法确认不误选；Esc回到触发按钮。
4. 打开设置，切换常规/工具/高级标签；读出选中/勾选/禁用状态，键盘不越过模态边界；关闭后回到原按钮。
5. 打开 `/parameters.html`，尝试缺必填提交：错误与输入关联，焦点落到首错；区域/工位选项加载、选择和父级切换清空能理解。
6. 打开 `/designer.html`，逐个切换分区与工具，核对选中目标、字段标签及预览名称；保存/冲突/未应用配置反馈可理解。
7. 打开 `/product.html`，选中炉号并查看关联详情；详情标题可读，Esc返回同一业务单元格；草稿离开保护可操作。
